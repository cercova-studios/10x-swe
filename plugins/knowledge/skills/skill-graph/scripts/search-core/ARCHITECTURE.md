# Skill Search architecture

## 1. Purpose
Rust CLI for offline local skill discovery and explicit remote discovery. SQLite is a rebuildable metadata index. Existing graph.json and skill folders remain authoritative.

## 2. Layers
main.rs owns arguments and JSON output. catalog.rs owns SQLite import, search and neighbors. registry.rs owns bounded public skills.sh discovery and pinned GitHub bundle retrieval. bundle.rs owns filesystem validation, fingerprints and receipt-gated loading. scanner.rs owns the isolated scanner adapter. promotion.rs owns explicit new-folder installation and graph rebuild. No daemon or MCP server.

## 3. Storage
Default state is ~/.agents/knowledge/skills/search. CLI --state overrides it. catalog.sqlite stores metadata only; quarantine holds immutable copies and provenance; receipts hold scanner evidence. No credentials persist. Graph default is ~/.agents/knowledge/skills/graph.json.

## 4. Shared module contract
All public functions return anyhow::Result. JSON interchange uses serde_json::Value. catalog::refresh(graph: &Path, db: &Path), search(db: &Path, query: &str, limit: usize) -> Value, neighbors(db: &Path, id: &str) -> Value. registry::search(query: &str, limit: usize) -> Value; registry::prepare(id: &str, destination: &Path) -> Value returns origin, revision and path metadata after copying a complete verified subtree. Registry never calls scanner or emits instruction bodies. bundle/scanner/main are integrator-owned.

## 5. Domain types
Local identity is a scoped graph ID. Remote identity includes repository, actual skill path and commit. A prepared bundle is a directory plus locally computed fingerprint and provenance. An accepted receipt binds scanner identity, exact fingerprint and covered files. Popularity is relevance metadata, never acceptance.

## 6. Local freshness
Search verifies entrypoint hashes, declared backlinks and current root/alias inventory in Rust before importing the same checked graph value transactionally. No second pathname read can replace that value. No implicit remote request. Local load follows existing user policy and reports historical acceptance separately; remote load always requires an accepted exact-bundle receipt. Existing graph identity overrides and cycles are preserved.

## 7. Retrieval
FTS5 BM25 over name and description. Search returns at most20metadata results. Workflow neighbors filter only uses; related links never become dependencies. SQLite schema2 stores typed source/target/relation triples and is rebuilt transactionally. `path` returns at most10candidate routes, each with at most5suggested steps, conditional routes and alternative project implementations. Lexical retrieval is model-free; --semantic explicitly embeds the task locally. Cosine0.65 and lexical60%-of-best thresholds are uncalibrated. Selection, capability coverage, conflict resolution and execution ordering remain the agent's job. No query loads bodies or executes a skill.

## 8. Remote access
Explicit remote search uses the public endpoint employed by the official skills CLI. GitHub resolves a real commit and searches the actual file tree. Requests have timeouts, response limits and finite file counts. No shell interpolation, fetched code execution, dependency installation, or credential discovery.

## 9. Extension points
New registry adapters must implement the same bounded metadata and pinned complete-bundle contract. Explicit local embedding map/query commands use the existing installed runtime. Explicit installation supports only a fresh folder under a registered root with no skill-graph metadata. Before persisting remote additions or updates, the agent workflow reviews clarity, concision and overlap, reuses exact copies or consolidates shared guidance, and retains provenance/license notices. Any edited final bundle requires renewed exact-bundle acceptance. This editorial review is an agent procedure, not a classifier verdict or a mechanically enforced proof in the CLI. Relationship-bearing bundles and replacements require existing graph staging, annotation and renewed scan. Public search responses cache for 60 seconds; errors never become successful empty results or silent stale fallback.

## 10. Invariants
Reject traversal, symlinks, secret files, excessive size/count/depth, ambiguous paths and partial downloads. Remote search cannot return instructions. Failed, incomplete, rejected or changed scans cannot load. Only third_party_content_exposure alone may be informational under installed scanner policy. Scanner coverage must match all bundle files. Scan a private verified snapshot; compare actual returned bytes with inventoried digest. No downloaded code executes. Receipts are tool evidence, not universal filesystem enforcement or protection against a malicious process controlling the same user account.

## 11. Operations
Explicit `refresh` rebuilds the registered inventory using the installed graph Python runtime/helper, validates it in Rust, rebuilds the local semantic map using `topics::build_map`, then creates/replaces the catalog transactionally from the final checked graph. `--graph` must select a graph.json with sibling roots.json. Each stage stops on failure; earlier completed stages may remain published. No active skill files change. Quarantine preparation uses a fresh staging directory and publishes only after success. Failures exit nonzero with stderr JSON. Scanner uses the pinned reviewed Apple container image and an inherited token; starting its service is an explicit operation. Build with locked Cargo dependencies. Promotion and the updated Python writer share .skill-graph-lock in the graph directory; manual or legacy writers must not run concurrently. Lock acquisition precedes the bound snapshot read. Graph publication stays on the graph filesystem; rollback stays on the target filesystem in a hidden retained folder and records its path in quarantine. Failed graph writes restore only this operation's exact bytes. Stale locks after force termination require inspecting the recorded operation before removal. Existing identity overrides survive because the graph builder parses current skill frontmatter.

## 12. Cloud classification

An explicit `classify QUERY --allow-cloud --mode shortlist|catalog --min-fit VALUE` command sends the provided query and global skill metadata to TypeSafe. Use synthetic/public queries; the caller is responsible for query content. Project classification is disabled. It never sends bodies or paths, searches remote registries, loads a skill, or grants acceptance. Offline search remains the default.

Shared adapter API: `jev::classify(query: &str, candidates: &[serde_json::Value], state: &Path, min_fit: f64) -> anyhow::Result<Value>`. Candidates supply local id/name/description. One bounded request asks an independent absolute-fit Noul for each candidate; rank those probabilities and reject when the winning candidate falls below the explicit threshold. Empty shortlists abstain without a request. The adapter accepts at most254 candidates, pins jev-1.13.0 and criteria version, validates exact question coverage and finite probabilities, uses TYPESAFE_API_KEY (JEV_API_KEY fallback) from the environment without persisting it, and returns model, selected_id, fit_probability, ranked IDs/probabilities, raw answers, current uncached usage, historical inference usage, timing and cache status. Cache binds exact payload/model/criteria; failed responses never cache as success. Requests are bounded HTTPS POST to api.typesafe.ai/v1/systemone, no redirects, retries or credential discovery. Invalid or missing inference exits visibly; offline search remains available separately.

## 13. Acceptance
Fixture tests cover scoped aliases, query metacharacters, negatives, traversal, symlink escape, changed receipts, missing coverage and scanner failures. Live public metadata requests and isolated benign scans are separate from fixture results.

## 14. Keep this document honest
Update with changes to storage, shared APIs, acceptance rules, remote endpoints, freshness, promotion or default paths. Keep command behavior, prerequisites and operating bounds current.

Search is offline by default. `search QUERY --remote` adds skills.sh metadata alongside local results, retaining separate local/remote origins. `--remote` conflicts with `--only-global`.

Public audit summaries: registry::search enriches returned public IDs through www.skills.sh/api/v1/skills/audit with bounded provider metadata and report URLs. All audit lookups share10seconds; at most16providers and128KiB per response. Failures/missing data remain unavailable and do not fail skill discovery. Registry audit dates are retained; no exact fetched-content fingerprint is provided, so our independent acceptance gate remains mandatory. Cache adapter is versioned for the new result schema.

## Terminal graph view
`skill-search graph [ID]` renders verified local graph metadata read-only with Ratatui/Crossterm. It creates no catalog or layout state, loads no skill bodies and contacts no providers. Scoped identities and canonical alias resolution remain intact. Fresh inferred clusters seed islands; connected components provide the fallback. Geometry aggregates cluster members and incident edges at scale greater than45; zoom, filtering or neighborhood focus reveals individual skills. Only recorded typed edges draw. Dotted edges indicate inferred-only geometry; details preserve direction, relation and status when overview edges aggregate.

Camera targets ease at an active33ms frame cadence. Cursor-anchored wheel zoom, background dragging, click selection/cluster expansion and session-only node pins complement keyboard controls. Local bounded repulsion uses a spatial grid with at most128 comparisons per node, existing same-cluster edges supply springs, and initial anchors retain the map's structure. Physics runs at most120 startup ticks (90 after dragging/unpinning), stopping early after eight low-motion ticks. This is a deterministic visual heuristic, not semantic inference. Space pauses physics and makes camera controls immediate. Positions and pins are not persisted.

The graph fills the terminal width and all rows except one status row and one control row. Skill list (`s`), selected details (`d`) and help (`?`) are optional overlays; search opens the list. Escape closes overlays before quitting. Overlay rectangles block graph mouse events without resizing the viewport or changing camera coordinates.

Node glyphs overlay Braille edges. Labels prioritize selection/neighbors and avoid occupied node/label cells; long labels clip by display width. A minimap provides camera context. Bounds remain2048nodes/16384edges; malformed endpoints fail before terminal takeover. Initialization fits the graph; small screens suspend the canvas and retain quit controls. RAII restores raw mode/cursor/alternate screen and disables mouse capture on normal exit and handled errors; Ctrl-C quits. Non-TTY calls fail with guidance. Idle polling blocks up to250ms without drawing; mouse and resize events redraw. Headless tests cover camera convergence, cursor anchoring, pin stability, finite deterministic layout, typed-edge retention, Unicode labels and small screens; real PTY checks cover mouse/keyboard navigation, idle output, resize and terminal restoration. External SIGKILL cannot restore terminal state; use reset after a forced kill.

## Conceptual map and Obsidian interchange
The conceptual map covers registered canonical skills in one typed relationship graph. Explicit uses remain directed and authoritative; observed body references are references; inferred cosine links are suggestions, never instructions or acceptance. `map` explicitly builds a bounded local BGE map through existing source-insights runtime/helper and cache; no model download/cloud call. Bodies are bounded and chunk-located; fingerprint/model/extraction settings bind the result. Greedy modularity communities expose emergent groups, with cross-community bridge scores and secondary memberships. Clusters are heuristic, not a domain ontology. `clusters` and `related` read the map without models, subprocesses or state writes; cluster queries use lexical member relevance; related retrieval exposes bounded incident typed links. The TUI displays the unified graph with cluster geometry; details identify relation types and inferred status.
`vault --output PATH [--include-inferred]` produces a fresh local Markdown vault from canonical skill notes and Markdown references, preserving bodies/licenses. Frontmatter uses top-level quoted Wikilink lists (`uses`, `references`, `related`, `topic-clusters`, `used-by`) and standard list `tags`/`aliases`; folders mirror scoped IDs to prevent same-name collisions. Exact aliases remain aliases, differing versions remain separate. Body links are rendered alongside matching frontmatter pointers; guidance is not duplicated. Default export omits inferred related/topic links; explicit --include-inferred marks the mapping as unreviewed and creates inferred topic notes. No live skill files change. Native skill-graph maintenance supports these typed link fields and verifies targets/body presence, with generated incoming mirrors. Existing bare-ID metadata remains supported for unchanged installed skills; newly authored portable links use the top-level schema. Derived mapping never self-promotes guessed relationships into active skills. Export/import round-trip must verify link resolution and declared relationship equivalence.

## Mapping lifecycle and route planning
Map writes are explicit, serialized by the shared graph lock, bound to a checked inventory snapshot and backed up before publication. Cache is plain SQLite at state/concepts.sqlite; model processes are short-lived. Helper output is capped at1MiB/stdout and128KiB/stderr with180seconds wall time; generated maps are capped at16MiB. Rebuild preserves a fresh mapping when identities/hashes match, otherwise marks it stale. Path/cluster reads require fresh provenance; ordinary search and declared routes remain usable. Vault exports reserve a fresh destination, stage Markdown only and clean failed exports; bounds128MiB/8192files.
