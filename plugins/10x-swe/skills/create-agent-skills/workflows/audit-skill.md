# Audit a selected skill

Use the exact target from the request. If missing, list bounded candidate metadata
and ask for selection. Do not load the entire inventory or force a redundant intake.
Read `references/skill-structure.md` and the target's entrypoint and retained resources.

Check the actual capability contract: triggers, input/output identity, tools, paths,
credentials, external effects, time/byte limits, failure behavior and authority.
Compare overlaps with existing skills before adding abstractions or deleting routes.
Verify provenance/licenses, relative resources, metadata and graph declarations.
Separate executable helpers from source data; inspect their behavior and dependencies.
Review clarity and useful progressive disclosure, not compliance with an XML style.

Record keep/link/consolidate/remove-proposal decisions with inspected evidence.
Retain distinct specialist capabilities. Do not delete unique skills based on names,
similarity scores or arbitrary length targets. For authorized edits, stage the
smallest coherent change, exercise a public task and failure path, preserve a backup
and check for concurrent edits before promotion. Otherwise return a concrete diff.
Rebuild/check affected graph inventory when registered. Report checks, failures,
unverified claims and any retained compatibility with its owner/removal condition.
