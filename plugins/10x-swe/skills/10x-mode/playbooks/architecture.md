### Architecture

1. State the question, the decision it supports, and what evidence would change the answer.
2. Read and follow [[plugin/10x-swe/code-research/SKILL]].
3. When the outcome is a structural proposal, read and follow [[plugin/10x-swe/improve-codebase-architecture/SKILL]] for the affected area.
4. When the user asked to stress-test an idea, read [[plugin/10x-swe/grill-me/SKILL]]. When they asked to use external documentation, read [[plugin/10x-swe/grill-with-docs/SKILL]].
5. When the user explicitly asked for a repository-wide architecture review, read [[plugin/10x-swe/deep-architecture-analysis/SKILL]] and stay inside authorized analysis.
6. If the question depends on a domain listed in 10x-mode, read that skill's `SKILL.md` before answering.
7. Answer with measured, inferred, and guess labels. Do not edit unless the user asked for a change. Then switch to feature or refactor.
